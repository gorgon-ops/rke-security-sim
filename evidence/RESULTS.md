## Numbers behind the verdicts

- **Rolling code:** 1000/1000 legitimate presses accepted; 0/1000 replays accepted.
- **Relay (no defence):** 1000/1000 live-relayed codes accepted — rolling codes cannot stop relay.
- **RollJam:** 1000/1000 jam-and-replay attempts unlocked the car.
- **MAC forgery:** keyless checksum forged in **1** attempt (no key). Keyed HMAC: **0** forgeries in 500,000 guesses (expected work ≈ 2³¹).
- **CAN injection:** SecOC ON → car moved 0 m (gear P). SecOC OFF → car moved 8.05 m to 27.5 kph (gear D).
- **Signed-command replay:** first frame accepted; 0/100 replays of that exact signed frame accepted (freshness counter).
- **Telematics:** owner forwarded=true, attacker blocked=true.

## Design sweep — how much timing precision must distance bounding buy?

The τ threshold is not a free knob: it is bounded below by how noisy your
ranging is. For each timing jitter **σ**, we pick the *tightest* τ an honest
owner tolerates (false-reject ≤ 0.1%) and measure the relay success that
σ leaves on the table. Attacker relays from 15 m (+20 ns hardware latency); honest fob at 0.3–2 m; 300,000 trials per σ.

| σ (ns) | ≈ ranging accuracy | tightest τ | relay success | honest false-reject |
|---:|---:|---:|---:|---:|
| 0.7 | 0.1 m | 14.6 ns | 0% | 0.1% |
| 2 | 0.3 m | 17.7 ns | 0% | 0.1% |
| 5 | 0.75 m | 25.8 ns | 0% | 0.1% |
| 15 | 2.25 m | 55.2 ns | 0% | 0.1% |
| 30 | 4.5 m | 100.3 ns | 25.55% | 0.1% |
| 60 | 8.99 m | 192.7 ns | 88.64% | 0.1% |

_Honest false-reject is held at the budget in every row — the free variable is
residual **relay success**. At UWB precision (σ≈0.7 ns, ~10 cm) the relay is
crushed to 0% with no honest cost; as ranging degrades past ~2 m the far
relay hides in the timing noise (σ=30 ns → 25.55%, σ=60 ns → 88.64%). So distance bounding is not a
fragile compromise — it is **decisive if and only if you buy UWB-class timing**,
which is exactly why the CCC Digital Key standard uses UWB. This table is a
procurement spec, not a single configuration._

## Tradeoff curve — rolling-code resync window (λ swept)

B = out-of-range presses ~ Poisson(λ); attacker sniffs one unused code at random offset K∈1..B. 300,000 trials per point. Table shown for λ=2; full λ∈{0.5, 1, 2, 4} sweep is in `report.json`.

| window W | honest lockout | attacker capture-replay |
|---:|---:|---:|
| 1 | 86.5% | 49.77% |
| 2 | 59.47% | 72.7% |
| 4 | 14.23% | 85.17% |
| 8 | 0.1% | 86.49% |
| 16 | 0% | 86.5% |
| 32 | 0% | 86.5% |
| 64 | 0% | 86.5% |
| 256 | 0% | 86.5% |

_Both columns are measured and move oppositely with W: a narrow window shrinks
the odds a sniffed unused code still lies inside it (capture-replay) but
desyncs honest users who pressed out of range (lockout). Widening W trades one
for the other. λ-sensitivity (honest lockout at W=4): λ=0.5→0.17%, λ=1→1.85%, λ=2→14.23%, λ=4→56.62%._
